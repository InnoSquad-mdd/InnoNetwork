# InnoNetwork 6.1.0 Release Notes

Status: Draft (unreleased)

Release date: TBD

This candidate is layered after the local 6.0 release cut. It must not be
tagged or published before InnoNetwork 6.0.0 and its required consumer gates
have completed.

## Added

- Bounded transport admission with independent request/stream capacity, queue
  deadlines, origin partitioning, and structured policy decisions.
- Advanced monotonic token-bucket and sliding-window rate limiting, bounded
  scope state, `Retry-After`, and opt-in IETF draft-11 response feedback.
  Invalid numeric policies fail closed, dormant replenished scopes are
  reclaimed, and quota is rechecked at physical dispatch after admission.
- Phase-aware streaming timeouts plus control-aware SSE cursor/retry metadata
  and bounded reconnect-on-EOF behavior.
- Vendor-neutral logical request and child physical-attempt spans with bounded
  export. Cache hits and coalesced followers do not fabricate attempt spans.
- Server-confirmed resumable upload chunks with atomic, credential-free
  checkpoints and one private immutable snapshot shared by incremental identity
  hashing and chunk reads.
- Caller-owned streaming cursors with validated custom header names, 4 KiB
  cursor bounds, explicit reset semantics, transient-only resume, and no
  automatic redirects. Cursor contents remain application-owned and are not
  persisted or interpreted as an exactly-once acknowledgement.
- Response-scoped `makeDecoder()` factories and an opt-in aggregate SSE event
  byte limit. SSE empty data, multiline whitespace, inherited IDs, metadata-only
  blocks, BOM position, and CR/LF/CRLF framing are corrected. Stateful consumers
  should follow the migration in the DocC `StreamingGuide`.
- `NetworkOperationDeadline` adds an opt-in, operation-wide monotonic latency
  budget for buffered `OperationNetworkClient` requests.
- `NetworkOperationDeadlineStage` and `NetworkFailure.deadlineStage` identify
  the coarse stage that exhausted the budget without retaining URLs, headers,
  bodies, or arbitrary underlying error text.
- Deadline recovery continues to require a replay-safe HTTP method or an
  explicit stable idempotency key. Coalesced callers retain independent
  budgets even when they share one underlying transport request.
- `UploadManager.pause(_:)` and `resume(_:)` add idempotent interactive
  controls, and `UploadState.paused` survives background restoration as
  durable user intent.
- `UploadManager.retry(_:with:fromFile:)` reuses a failed logical task only
  when the caller supplies refreshed inputs with the exact original
  application-owned `Idempotency-Key`. Destination and method changes,
  cancelled/completed tasks, missing source files, and changed keys fail
  before a replacement system task starts.
- `ResponseCachePolicy.staleIfError(wrapping:)` adds origin-authorized stale
  recovery for `500`, `502`, `503`, `504`, timeout, and reachability failures.
  The cached response must carry one valid `stale-if-error=N` directive and
  remain inside that window; `no-store`, `must-revalidate`, malformed or
  duplicate directives, cancellation, and non-transient failures fail closed.
- `ResponseCachePolicy.requestOnlyIfCached(wrapping:)` honors request
  `Cache-Control: only-if-cached` only when explicitly wrapped. A reusable
  cache hit returns without transport, stale-while-revalidate suppresses its
  background leg, and a miss or forced revalidation produces a typed local
  configuration failure.
- Post-audit lifecycle hardening keeps active upload retries controllable,
  emits one terminal event per logical request, retains live circuit-breaker
  probes and committed quota reservations, and records the initial operation
  deadline stage before racing the timer.
- Final contract hardening isolates half-open probes from older coalesced
  transports, preserves cancellation across decoding interceptors, makes
  streaming total deadlines independent of noncooperative callbacks, records
  authentication replays as distinct physical spans, and enforces exact-case
  upload retry methods.

Existing operation starts without a deadline are source- and
behavior-compatible with 6.0. URLSession request/resource timeouts remain
separate transport controls, and separately returned streaming sequences are
not covered by the buffered operation deadline.
